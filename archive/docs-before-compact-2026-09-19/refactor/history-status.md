# Reading the decision history

The entries under this directory record a changing design. Read [current state](current-state.md) for what `libs/` does now. Read [the FDM review](../../libs/review/CODE_REVIEW.md) for newly found risks that have not yet been resolved. The entries below are useful evidence, but their original status words do not describe the current implementation.

| Earlier entry | Current reading |
|---|---|
| [Target architecture](architecture/overview.md), [D15](mesh-data/d15.md) | The original no-geometry DTO became a `Mesh` with optional geometry loaded explicitly. The batch runner remains unfinished. |
| [D4's drafts](pool/d4.md), [D5](pool/d5.md) | The implemented `Pool` uses `item_selector(done, error)` and `item_handler(item)`; the `get_next`/`admit` condition-variable interface is historical. |

| [D8–D11](pool/README.md), [D14](pipeline/d14.md) | These specify timeout, budget, status, and interrupt behavior for the **future batch runner**. `libs.pool` does not yet connect the preparation walk to a `--one-file` child. D14's interrupted-write safety argument must be checked against the current direct final-path writes before orchestration adopts it. |
